# Data Model

## ScenarioConfig

One checked-in YAML file describes one deterministic run case.

| Field | Type | Rule |
|---|---|---|
| `scenario_id` | string | Unique, stable ID within the split. |
| `split` | enum | `training`, `validation`, or `evaluation`. |
| `world` | repo-relative path | Must be `simulation/worlds/obstacle.sdf`; no generated or edited world. |
| `seed` | unsigned integer | Required, fixed before a run; passed to `gz sim --seed`. |
| `lighting_id` | string | `obstacle_world_default` in this feature; the protected world lighting is not varied. |
| `unseen_condition_tags` | string array | Marks evaluation conditions not represented in training, including `unseen_obstacle_placement`; derived by the split validator, not inferred from the full tuple alone. |
| `start_pose` | `{x_m,y_m,z_m,roll_rad,pitch_rad,yaw_rad}` | World coordinates. `z_m` starts from the existing model pose unless an explicit reset is required. |
| `obstacle` | `{entity,collision,pose}` | Existing named obstacle collision and its unchanged world position/orientation from the world SDF. |
| `commanded_speed_mps` | positive float | Bounded by controller configuration; default cap 2.0 m/s. |
| `stop_distance_m` | positive float | Initial 5.0 m obstacle-to-front-plane stop-trigger threshold; validated in P3 before data collection and frozen in the split manifest. It is not the measured stopping travel. |
| `corridor_half_width_m` | positive float | Covers the vehicle collision width plus documented margin; default 5.5 m. |
| `ground_z_min_m` | float | Lowest accepted point in `base_link`; derived from the SDF frame/ground plane and verified with a ground-only cloud before use. |
| `run_timeout_sim_s` | positive float | Maximum simulated duration for runner; configured per scenario. |

Canonical tuple for split isolation is the serialized numeric tuple:

```text
(start_pose, obstacle.entity + obstacle.collision + obstacle.pose, commanded_speed_mps)
```

Values are normalized to fixed decimal precision before comparison. No tuple may occur in more than one split. A different seed, run index, lighting ID, or filename does not create a different scenario. Separately, evaluation configs are tagged by condition: an obstacle entity/pose absent from training is `unseen_obstacle_placement`; the current lighting is always recorded as `obstacle_world_default`. Lighting generalization is not tested in this feature because changing world lighting is out of scope. The evaluation split contains exactly ten configs and its SHA-256 manifest is generated before training.

## SplitManifest

Stored beside generated dataset metadata under `artifacts/` and regenerated by the scenario validator.

| Field | Type | Rule |
|---|---|---|
| `schema_version` | string | Dataset/split schema version. |
| `created_utc` | ISO 8601 string | Wall time for audit only, never used in control. |
| `scenario_files` | map | Relative config path, split, scenario ID, full tuple, seed, and SHA-256. |
| `evaluation_frozen` | boolean | Must be true before first model training command. |
| `evaluation_manifest_sha256` | hex string | Hash over sorted IDs, tuples, seeds, and config hashes. |
| `generator_version` | string | Script version/commit identifier that produced the manifest. |

Training refuses missing evaluation freeze metadata, duplicate full tuples, or a mismatch between the current evaluation files and their frozen hashes.

## LabeledFrame

The data collector writes lossless PNG frames below `artifacts/datasets/<dataset_id>/images/` and one row per accepted frame in `labels.csv` (or equivalent JSONL when nested metadata is required).

| Field | Type | Rule |
|---|---|---|
| `sample_id` | string | Stable unique sample ID. |
| `image_path` | relative path | PNG under the ignored dataset directory. |
| `image_stamp_ns` | integer | ROS header stamp in simulation time. |
| `lidar_stamp_ns` | integer | Paired point-cloud simulation stamp. |
| `lidar_age_ns` | integer | Must be non-negative and no greater than one 15 Hz lidar period (66,666,667 ns). |
| `scenario_id`, `split`, `seed` | string/string/uint | Must match frozen config and manifest. |
| `scenario_sha256` | hex string | Binds sample to exact config. |
| `nearest_obstacle_distance_m` | float or null | Measured after transform to `base_link`, from front collision plane to nearest non-ground forward-corridor return. Null only for invalid/unlabelable frames. |
| `label` | enum | `too_close`, `clear`, or `invalid`; positive iff distance is at or below the stop-trigger threshold `stop_distance_m`. `invalid` rows are excluded from training and metrics. |
| `label_rule_version` | string | Identifies geometry/filter and threshold semantics. |

Frames with absent/stale lidar, bad timestamps, invalid image dimensions/encoding, or no verified transform are dropped or recorded as `invalid`; they are never silently labeled `clear`. Training reads only `split=training`; validation controls checkpoint/threshold selection; evaluation is read only after all choices are frozen. Before held-out scoring, require at least 100 valid `too_close` and 100 valid `clear` images overall, with at least five images of each class from every evaluation scenario. If either quota is unmet, mark evaluation support insufficient and fail SC-004; do not substitute validation samples.

## DetectorArtifact

Files under `artifacts/models/<model_id>/`:

- `weights.pt`: plain PyTorch `state_dict`; loaded on CPU with safe weights-only loading.
- `metadata.json`: architecture ID, input shape `3x120x160`, RGB normalization, PyTorch version, training scenario hashes, validation scenario hashes, chosen validation threshold, class IDs, and source code/version identifier.
- Evaluation metrics are stored separately and do not modify training metadata or weights.

Evaluation scenarios and samples are not included in training or model-selection metadata. Metrics are labelled as simulation-prototype results.

## ControllerSession

One autonomous trial, identified by run UUID, mode (`lidar` or `ai`), scenario config/hash, seed, and condition tags.

State progression:

```text
WAITING_FOR_CLOCK_AND_SENSORS -> READY -> MOVING -> STOP_REQUESTED -> RESTED -> COMPLETE
                   |                |        |                |
                   +-> SAFE_STOP <--+--------+----------------+
```

`SAFE_STOP` is entered on stale/invalid required lidar or odometry, command expiry, model fallback failure, clock rollback/reset, or shutdown. In AI mode, stale AI alone selects the `lidar` branch; it does not disable the lidar controller. State changes use simulation time; wall-clock time is retained only for operator diagnostics.

`COMPLETE` means the configured rest condition has been met (speed below the configured threshold for the settling interval) and the record has been flushed; it does not mean the obstacle-stop outcome was successful. If the scenario's simulation-time limit expires first, use `trial_status=timed_out`; if reset, shutdown, a competing command writer, or a runtime lighting mismatch ends the attempt first, use `trial_status=aborted`. Record the specific cause in `completion_reason`. A reset gets a fresh run UUID and never overwrites the prior attempt.

## EvaluationRecord

One row per scenario and behavior in `docs/evaluation/results.csv`.

Required fields:

`run_id`, `scenario_id`, `scenario_sha256`, `split`, `mode`, `seed`, `lighting_id`, `condition_tags`, `start_pose`, `obstacle_entity`, `obstacle_collision`, `commanded_speed_mps`, `detected`, `detection_source`, `detection_stamp_ns`, `stop_request_stamp_ns`, `stopped_before_contact`, `stopping_distance_m`, `trial_status`, `completion_reason`, `collision_status`, `collision_coverage`, `collision_entity`, `collision_stamp_ns`, `ground_contact_excluded`, `sensor_stale_events`, `sim_duration_s`, and `package_versions`.

`stopping_distance_m` is measured stopping travel: the odometry path length from the first final zero-command output until the rest criterion is met. It is distinct from `stop_distance_m`, the obstacle-to-front-plane trigger and label threshold. `collision_status` is `collision` only when a contact event names the scenario's allowlisted non-ground obstacle collision; it is `no_collision` only when coverage of relevant vehicle contact surfaces is verified and no such event occurred; otherwise it is `unknown`. `collision_coverage` is `verified`, `limited`, or `stale`; ground is always excluded. P1/P3 must demonstrate that the existing chassis contact sensor covers selected obstacle interactions. Wheel-only contacts not visible to it make the trial's collision status `unknown` and block a zero-collision claim.

`trial_status` is `completed`, `timed_out`, or `aborted`. A `completed` trial reaches the rest condition and flushes its record, irrespective of whether it stopped before contact. Simulation-time limit expiry uses `timed_out`; reset, shutdown, a competing command writer, and a detected runtime lighting mismatch use `aborted`, with the specific cause in `completion_reason` (the lighting value is `lighting_mismatch`). Every planned scenario/mode remains in the evaluation denominator; timed-out or aborted trials count as failures, and retries use a new run UUID without replacing the original record. An uninterrupted P5 evaluation has one planned row for each of ten scenarios and each behavior; any interrupted attempt is retained and prevents the affected evaluation from passing.

The paired P5 output has one lidar and one AI planned row per frozen evaluation scenario, with identical scenario hash, start pose, obstacle placement, speed, and seed. Reports also group results by `condition_tags`; fixed default lighting is not evidence of lighting generalization.
